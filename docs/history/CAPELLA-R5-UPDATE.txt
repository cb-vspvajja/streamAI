StreamAI Capella package update r5

Fixes sessions appearing in Capella Agent Tracer with no messages.

The installed agentc 1.1.2 SDK accepts typed Content objects. The previous
gateway passed dictionaries, so the begin event was stored but the next
event failed with AttributeError: 'dict' object has no attribute 'kind'.

Changes:
- Validate and convert events into the SDK's public Content models.
- Use tool_result for tool outputs and supported event types for errors.
- Correlate each tool call with its result using a unique call identifier.
- Preserve viewer/trace/response metadata in the SDK's extra field.
- Close a span when its first message fails.
- Report a logging failure instead of claiming a missing trace was logged.
- Record the actual native session ID in the demo's operational trace.
- Includes the previous r2, r3 and r4 package fixes.

To update an existing extracted Capella package:
1. Save streamai-capella-r5-update.zip in Downloads.
2. In Terminal, enter your existing couchbase-stream-ai-v2.1.3-capella folder.
3. Run:
   unzip -o "$HOME/Downloads/streamai-capella-r5-update.zip"
4. Rebuild and restart only the UI:
   bash -c 'source scripts/capella-common.sh; compose build ui; compose up -d --no-deps ui'

Sign in again if requested. Run MCP proof or send a new chat message. In
Capella Agent Tracer, select your cluster, bucket streaming, and the current
session. Refresh its logs and clear message-type filters if necessary.
Earlier failed events are not automatically reconstructed.

Storage in this configured package (verified with agentc 1.1.2):
- Native Tracer: streaming.agent_activity.logs
- Agent Catalog: streaming.agent_catalog.tools, prompts and metadata
- Demo trace projection: streaming.recommendations.traces
- Agent Memory users/sessions: agent_memory.agentmemory.users and sessions
- Short- and long-term blocks: agent_memory.agentmemory.memory
  annotations.memory_scope distinguishes short_term from long_term.
  Short-term blocks use SHORT_TERM_TTL_SECONDS; long-term writes request
  memory_block_ttl=0. A bucket/collection maxTTL may still impose expiry.
- Resumable UI state/cache: streaming.viewers.app_state
- Operational viewer profile: streaming.viewers.profiles

MCP proof logs a tool execution; it does not save conversational memories.
To create memory, send a chat turn. An explicit preference such as
"I prefer science fiction movies" also triggers a long-term fact write.
Processing is asynchronous; inspect the memory collection after it completes.

This update does not include capella.env, certificates or catalogue data.
See VALIDATION.md for the checks performed and their limits.
